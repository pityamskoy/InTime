# Backend вСрок

## Описание проекта

Это бекенд веб-сайта вСрок на Spring Boot, предназначенное для платформы по спасению еды. Приложение позволяет магазинам публиковать продукты с истекающим сроком годности по сниженным ценам, а пользователям — находить и покупать такие продукты, экономя деньги и уменьшая пищевые отходы.

## Основные возможности

- **Управление пользователями**: Регистрация, аутентификация, профили покупателей и владельцев магазинов
- **Управление магазинами**: CRUD операции для магазинов с геолокацией и верификацией
- **Управление продуктами**: Создание, обновление и удаление продуктов с информацией о сроке годности, цене и скидках
- **Система фильтрации**: Расширенная фильтрация продуктов по категориям, магазинам, расстоянию, названию
- **Система оценки продуктов**: Алгоритм расчета релевантности продуктов на основе цены, скидки, расстояния и рейтинга
- **Отзывы и рейтинги**: Пользователи могут оставлять отзывы о магазинах (1-5 звезд)
- **Избранное**: Сохранение любимых типов продуктов
- **Управление изображениями**: Загрузка и хранение изображений для продуктов, магазинов и категорий
- **Автоматическая очистка**: Планировщик задач для автоматического удаления просроченных продуктов
- **Геолокация**: Расчет расстояния между пользователем и магазинами

## Модель данных

### Основные сущности:

- **User** - Пользователи системы (покупатели и владельцы магазинов)
- **Shop** - Магазины с геолокацией, расписанием работы, верификацией
- **Product** - Продукты с ценой, скидкой, сроком годности
- **ProductType** - Типы продуктов с описанием, весом, калориями
- **Category** - Категории продуктов
- **Review** - Отзывы пользователей о магазинах
- **Favorite** - Избранные типы продуктов пользователей
- **Interest** - Интересы пользователей к продуктам
- **Image** - Изображения для продуктов, магазинов, категорий

## API Endpoints

### Пользователи (`/users`)

- `GET /users` - Получить всех пользователей
- `GET /users/{id}` - Получить пользователя по ID
- `POST /users/login` - Вход в систему
- `POST /users/create` - Создать нового пользователя
- `PUT /users/update` - Обновить данные пользователя

### Магазины (`/shops`)

- `GET /shops` - Получить все магазины
- `GET /shops/{userLat}/{userLon}` - Получить все магазины с расчетом расстояния
- `GET /shops/{id}` - Получить магазин по ID
- `GET /shops/{id}/{userLat}/{userLon}` - Получить магазин с расчетом расстояния
- `GET /shops/shop_stars/{id}` - Получить средний рейтинг магазина
- `POST /shops/create` - Создать новый магазин
- `PUT /shops/update` - Обновить данные магазина
- `DELETE /shops/delete` - Удалить магазин

### Продукты и лента (`/feed`)

- `POST /feed/{offset}` - Получить все продукты с пагинацией (deprecated)
- `POST /feed/products_by_shop/{id}/{offset}` - Получить продукты магазина
- `POST /feed/filtered/{offset}` - Получить отфильтрованные и отсортированные продукты
- `GET /feed/product/{id}` - Получить продукт по ID
- `POST /feed/create` - Создать новый продукт
- `PUT /feed/update` - Обновить продукт

### Типы продуктов (`/product_types`)

- `GET /product_types` - Получить все типы продуктов
- `GET /product_types/{id}` - Получить тип продукта по ID
- `GET /product_types/categories/{productTypeId}` - Получить категории по типу продукта

### Категории (`/categories`)

- `GET /categories` - Получить все категории
- `GET /categories/{id}` - Получить категорию по ID
- `POST /categories/create` - Создать новую категорию
- `PUT /categories/update` - Обновить категорию
- `DELETE /categories/delete` - Удалить категорию

### Отзывы (`/reviews`)

- `POST /reviews/{offset}` - Получить все отзывы с пагинацией
- `GET /reviews/{id}` - Получить отзыв по ID
- `POST /reviews/get_review_by_shop/{id}/{offset}` - Получить отзывы магазина
- `POST /reviews/create` - Создать новый отзыв
- `PUT /reviews/update` - Обновить отзыв
- `DELETE /reviews/delete` - Удалить отзыв

### Избранное (`/favorites`)

- `GET /favorites` - Получить все избранные
- `GET /favorites/{id}` - Получить избранное по ID
- `GET /favorites/user/{id}` - Получить избранное пользователя
- `POST /favorites/create` - Добавить в избранное
- `PUT /favorites/update` - Обновить избранное
- `DELETE /favorites/delete` - Удалить из избранного

### Изображения (`/images`)

- `GET /images` - Получить все изображения
- `GET /images/{id}` - Получить изображение по ID
- `POST /images/create` - Загрузить изображение (multipart/form-data)
- `PUT /images/update` - Обновить изображение
- `DELETE /images/delete` - Удалить изображение

### Интересы (`/interests`)

- `GET /interests` - Получить все интересы
- `GET /interests/{id}` - Получить интерес по ID
- `POST /interests/create` - Создать интерес
- `PUT /interests/update` - Обновить интерес
- `DELETE /interests/delete` - Удалить интерес

## Настройка и запуск

### Требования

- Java 25 или выше
- Maven 3.6+
- Docker и Docker Compose (для базы данных)
- PostgreSQL (или использование Docker Compose)

### Установка

1. **Клонируйте репозиторий:**
```bash
git clone https://gitlab.mai.ru/vsrok/backend
cd backend
```

2. **Настройте базу данных:**

Отредактируйте `src/main/resources/application.properties`:
```properties
spring.datasource.url=jdbc:postgresql://localhost:1234/postgres
spring.datasource.username=postgres
spring.datasource.password=root
```

3. **Запустите базу данных PostreSQL на порту 1234 удобным вам образом**

4. **Соберите проект:**
```bash
mvn clean install
```

5. **Запустите приложение:**
```bash
mvn spring-boot:run
```

Или запустите класс `Main` из IDE.

Приложение будет доступно по адресу: `http://localhost:8080`

## Конфигурация

### application.properties

Основные настройки приложения находятся в `src/main/resources/application.properties`:

- `spring.jpa.hibernate.ddl-auto=update` - Автоматическое обновление схемы БД
- `spring.jpa.show-sql=true` - Показывать SQL запросы (для разработки)
- Настройки подключения к базе данных

### application.yaml

Дополнительные настройки в YAML формате:
- Настройки multipart для загрузки изображений
- Конфигурация JPA и Hibernate

## Планировщик задач

Приложение использует `@Scheduled` для автоматической очистки просроченных продуктов:

- **Расписание**: Каждый час (`0 0 * * * ?`)
- **Функция**: Удаление продуктов с истекшим сроком годности и связанных интересов=

## Особенности реализации

- **DTO Pattern**: Разделение Entity и DTO для безопасности API
- **Mapper Pattern**: Автоматический маппинг между Entity и DTO
- **Repository Pattern**: Абстракция доступа к данным
- **Service Layer**: Бизнес-логика вынесена в сервисы
- **Async Configuration**: Настройка пула потоков для асинхронных задач
- **CORS**: Настроен для работы с фронтендом на `http://localhost:3000`

## Обработка ошибок

Приложение использует стандартные HTTP статусы:
- `200 OK` - Успешный запрос
- `201 Created` - Ресурс создан
- `400 Bad Request` - Неверный запрос
- `404 Not Found` - Ресурс не найден
- `422 Length Required` - Недостаточно данных

Кастомные исключения:
- `EntityNotFoundException` - Сущность не найдена
- `ImageFlowException` - Ошибка работы с изображениями
